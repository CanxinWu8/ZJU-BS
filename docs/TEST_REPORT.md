# 《B/S体系软件设计》企业智能协同审批系统 —— 测试报告

## 1. 测试概述与测试环境

### 1.1 测试目的
验证企业智能协同审批系统是否完整满足《实验：企业审批系统》任务书中的各项功能性需求、服务端强权限控制要求、金额精度与票据防重规则、高并发状态一致性以及容器化持久化能力[cite: 1]。

### 1.2 测试环境
- **宿主机环境**：Windows 11 + WSL 2 (Ubuntu 24.04 LTS)
- **容器编排环境**：Docker Compose v2 + MySQL 8.0 + Python 3.12 (FastAPI) + Nginx (Vue 3)[cite: 1]
- **测试工具**：Chrome 开发者工具（含移动端设备仿真）、cURL 命令行并发测试脚本、Swagger UI 接口测试台

| **TC-07** | 报销无票高亮与发票防重 | (1) 同一报销单两条明细绑定同一发票附件；(2) 明细勾选“无票支出”并填原因；(3) 跨报销单上传同一份 PDF 电子发票[cite: 1] | (1) 同单重复直接 400 阻断；(2) 财务界面红色高亮显示【无票异常支出】；(3) 触发 SHA-256 跨单重复票据红色预警横幅[cite: 1] | 同单防重阻断成功，跨单重复预警精确匹配出历史单号与上传人 | **通过** |
| **TC-08** | 自定义流程引擎与快照 | 管理员创建“企业公章使用审批 (`CUSTOM_SEAL`)” v1，员工提交申请后，管理员修改该模板字段并发布 v2[cite: 1] | 员工可直接使用动态表单提交；模板升至 v2 后，原已提交的 v1 申请详情与审批节点快照保持原样不被改写[cite: 1] | `snapshot_json` 完整锁死提交时版本 v1 与解析后的审批人 | **通过** |
| **TC-09** | 禁止自我审批规则 | 研发部经理 `mgr_rnd` 本人发起一笔采购申请（模板第 1 节点规则为“申请人所在部门负责人”）[cite: 1] | 系统检测到解析出的部门负责人为申请人本人，自动规避自我审批并上浮解析为企业负责人 `ceo`[cite: 1] | 节点 1 审批人自动解析为 `钱总(企业负责人)`，且本人调用审批接口返回 403 | **通过** |
| **TC-10** | 乐观锁并发冲突拦截 | 对处于 `IN_REVIEW` (`version=1`) 的申请单，同时发起两次审批请求（或同时发起审批批准与申请人撤回请求），均携带 `expected_version=1`[cite: 1] | 仅先到达数据库的请求更新成功（`version` 变为 2），后到达的请求因乐观锁条件不满足返回 `HTTP 409 Conflict`[cite: 1] | 第一个请求返回 200，第二个并发请求返回 `409 并发冲突拦截`，日志无重复 | **通过** |
| **TC-11** | 移动端适配与实时通知 | 将浏览器切换为 iPhone 14 Pro 视口（390×844），测试发起申请、审批与 SSE 实时弹窗提醒[cite: 1] | 界面自动切换为底部导航栏与卡片流，无横向滚动条；状态变化时手机端无需刷新立即弹出通知，点击直达详情[cite: 1] | 移动端触控交互流畅，SSE 2秒内实时弹出提醒并支持点击跳转 | **通过** |
| **TC-12** | 容器重启持久化验证 | 执行 `docker compose restart` 重启全部容器，重新登录查询历史申请、审批日志与未读通知[cite: 1] | 所有已提交申请、审批历史日志、上传的 PDF/图片附件及通知状态 100% 完整保留[cite: 1] | 重启后所有数据与文件流预览完全正常 | **通过** |

## 4. 测试结论

经全面验证，本系统在多部门 RBAC 权限隔离、三大固定业务与自定义动态表单校验、工作流快照与并发乐观锁、统计口径准确性以及移动端响应式与实时提醒等维度均达到设计预期
